# 基本介绍

**Speed Sheet** 是一款面向现代化 Web 应用的轻量在线电子表格引擎。

在**单元格模型**上，Speed Sheet 充分继承了经典开源表格（如 Luckysheet）成熟直观的属性规范（如 `v`, `m`, `f`, `ct`, 样式与合并属性）；但在**底层数据存储结构**上进行了关键重构：摒弃了老旧表格强绑定二维物理坐标（`data[r][c]` 容易产生大量 `null` 空白占位）、插删行列引发全量重写的问题，采用 **“稳定 ID (`rowId`/`colId`) + 顺序表 (`rowOrder`/`colOrder`) + 稀疏平铺 Map”** 的现代存储架构。

---

## 核心设计与解决的痛点

### 1. 彻底解决海量 `null` 空白占位问题
* **传统二维结构的包袱**：传统表格依赖二维密集矩阵（`data[r][c]`）或全量网格 `celldata`。当用户在第 100 行第 50 列输入数据时，中间会产生数千个无意义的 `null` 空白格占位，不仅严重消耗客户端内存，序列化传输与持久化体积也成倍膨胀；
* **Speed Sheet 稀疏存储**：平铺 Map 中**仅存储实际存在内容的单元格**，未填写的格子直接为空，绝无冗余 `null` 占位，大幅减轻内存占用与网络开销。

---

### 2. 攻克二维坐标在多人协同下的致命冲突

传统表格的物理坐标强绑定，在多人并发协同场景下存在天然的架构缺陷。

#### 典型协作冲突场景：
* 假设当前表格有 1000 行数据；
* **用户 A** 在第 2 行**插入了一个新行**；
* 与此同时，**用户 B** 正在编辑第 50 行的某个单元格。

#### 为什么传统二维架构会崩溃？
在 `data[r][c]` 物理坐标体系下，用户 A 插入一行后，第 2 行往后的所有单元格物理下标都必须全体 `+1`（触发 998 行单元格的海量数据重写与广播）。此时用户 B 提交的修改仍基于旧行号，合并时极易发生**大面积数据错位、覆盖他人修改甚至导致丢数据**！

#### Speed Sheet 的「稳定 ID + 顺序表」解法：
* **稳定 ID 与行号解耦**：每个单元格的 Key 绑定的是唯一稳定的行列标识（`r_<id>:c_<id>`），不随视觉行号改变；
* **插删行列零单元格重写**：用户 A 插入第 2 行，底层只需在 `rowOrder` 顺序数组中 `insert(2, newRowId)`，**已有 1000 行单元格的 Key 与数据完全不需要变动**；
* **协同无冲突收敛**：用户 B 编辑第 50 行，修改的依然是其对应的稳定 ID。两者的变更到达 Yjs CRDT 协调层时，可以**毫秒级完美合并，数据绝不错位也绝不丢失**，广播传输仅需一条极简的数组操作。

---

### 3. 开箱统一组件，无需业务适配两套代码
* 很多前端组件库过度拆包，单机用一个包、协同又要换另一个包。
* **Speed Sheet 解法**：统一对外暴露一个 `<SpeedSheet />` 组件，传入 `ydoc` 走原生多人协同，不传即为极速单机/纯查看态，业务调用极简。

---

## 核心技术栈

* **渲染层**：自研纯 Canvas 高性能视口按需重绘与事件调度
* **协同层**：Yjs CRDT 状态驱动
* **公式引擎**：常用计算函数支持（SUM、IF、VLOOKUP 等）
* **UI 展现**：Ant Design Vue 规范适配工具栏与弹层
