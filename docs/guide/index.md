# 基本介绍

**Speed Sheet** 是一款面向现代化 Web 应用的轻量在线电子表格引擎。

在**单元格模型**上，Speed Sheet 充分继承了经典开源表格（如 Luckysheet）成熟直观的属性规范（如 `v`, `m`, `f`, `ct`, 样式与合并属性）；但在**底层数据存储结构**上进行了关键重构：摒弃了老旧表格强绑定二维物理坐标（`data[r][c]` 容易产生大量 `null` 空白占位）、插删行列引发全量重写的问题，采用 **“稳定 ID (`rowId`/`colId`) + 顺序表 (`rowOrder`/`colOrder`) + 稀疏平铺 Map”** 的现代存储架构。

---

## 核心设计与解决的痛点

1. **从全量二维数组到「稳定 ID + 稀疏平铺」存储**：
   * 传统表格使用全量二维数组或包含全网格的 `celldata`，不仅会产生大量无意义的 `null` 空单元格浪费内存，更严重的是**单元格与物理行号列标 `(r, c)` 强绑定**。一旦在前面插入一行，后续成千上万个单元格的下标都需要整体递增重写，在多人协同下极易造成数据冲突与网络风暴。
   * **Speed Sheet 解法**：
     * **Cell 属性沿用经典规范**：单元格属性（值、公式、类型、样式）与经典规范深度对齐，业务心智零迁移；
     * **只存有效数据**：平铺 Map 中仅持久化实际有值的单元格，彻底消除空白 `null` 占位；
     * **插删行列零重写**：插入或删除行/列时，`cells` 中已有单元格的 key 完全不用变，只需对 `rowOrder` / `colOrder` 顺序数组做极小的增删调整，天生契合 Yjs CRDT 高并发协同；
     * **对外透明兼容**：无论是 UI 视口渲染、对外 API（`getCell(r, c)`）还是外部数据导入导出，依然对外呈现直观熟悉的 `r, c` 坐标。

2. **开箱即用的多人实时协同**：
   * 传统表格需要自己设计复杂的差量冲突解决机制，协同开发门槛极高。
   * **Speed Sheet 解法**：底层基于成熟的 Yjs (CRDT) 体系，所有单元格写入统一由事务调度，天然具备高可靠的多人并发协作能力。

3. **开箱统一组件，无需业务适配两套代码**：
   * 很多前端组件库过度拆包，单机用一个包、协同又要换另一个包。
   * **Speed Sheet 解法**：统一对外暴露一个 `<SpeedSheet />` 组件，单人模式、多人协同、只读查看仅需传参切换，业务调用极简。

---

## 核心技术栈

* **渲染层**：自研纯 Canvas 高性能视口按需重绘与事件调度
* **协同层**：Yjs CRDT 状态驱动
* **公式引擎**：常用计算函数支持（SUM、IF、VLOOKUP 等）
* **UI 展现**：Ant Design Vue 规范适配工具栏与弹层
