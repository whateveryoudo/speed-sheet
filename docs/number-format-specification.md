# 数字格式与日期时间转换规则规范（Number Format Specification）

本文档详细记录 `speed-sheet` 中的**数字格式系统（Number Format）**的设计理念、底层数据模型以及各项转换规则（尤其对齐语雀与 Excel 的日期时间序列号逻辑）。

---

## 1. 核心数据模型

在表格底层，每个单元格采用展示与存储分离的设计：

* **`v`（raw value 原始值）**：存储在 Yjs 文档和内存中的真实值，可以是数字（如 `1234.5`、`5`）、字符串（如 `"abc"`、`"2024-10-01"`）或布尔值。
* **`ct`（cell type / format 配置）**：单元格格式描述对象，形如：
  ```ts
  export interface CellFormat {
    fa: string // 格式模式串，如 "General", "@", "#,##0.00", "0.00%", "¥#,##0.00", "YYYY-MM-DD"
    t: 'g' | 's' | 'n' | 'd' // 类型：g=常规, s=字符串, n=数值, d=日期时间
  }
  ```
* **`m`（display value 渲染展示值）**：根据 `v` 和 `ct` 动态计算得出的最终显示文本。例如 `v: 5` 配上日期格式后，`m` 计算为 `"1900-01-04"`。

---

## 2. 转换规则概览

| 分类 | 类型 `t` | 典型格式串 `fa` | 原始输入 `v` | 转换后展示 `m` | 说明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **常规** | `'g'` | `General` | `1234.5` | `1234.5` | 原始值直接转字符串展示 |
| **纯文本** | `'s'` | `@` | `1234.5` | `1234.5` | 按字符串显示，左对齐，不参与数字格式化 |
| **数字** | `'n'` | `#,##0.00` | `1234567.8` | `1,234,567.80` | 千分位分割，补齐小数位数 |
| **百分比** | `'n'` | `0.00%` | `0.125` | `12.50%` | 数值乘以 100，末尾追加 `%` |
| **货币** | `'n'` | `¥#,##0.00` | `99` | `¥99.00` | 支持 `¥`, `$`, `€`, `£` 符号前缀与千分位 |
| **日期** | `'d'` | `YYYY-MM-DD` | `5` | `1900-01-04` | 支持序列号与标准日期文本 |
| **时间** | `'d'` | `HH:mm:ss` | `0.5` | `12:00:00` | 小数部分折算为一天内的时刻 |
| **日期时间**| `'d'` | `YYYY-MM-DD HH:mm:ss` | `5.5` | `1900-01-04 12:00:00` | 整数部分代表天，小数代表时刻 |

---

## 3. 日期时间与序列号转换深度解析

初次接触电子表格底层开发时，最容易让人困惑的是：**为什么输入纯数字 `5`，转成日期后会变成 `1900-01-04`？为什么输入 `-5` 会变成 `1899-12-25`？**

### 3.1 序列号系统（Serial Date System）的起源

1. 电子表格（Excel、语雀、Google Sheets、WPS 等）底层**没有独立的日期数据类型**，所有的日期与时间本质上都是**浮点数**。
2. 1983 年最早的电子表格 Lotus 1-2-3 将 `1` 设定为 `1900年1月1日`。但 Lotus 开发者犯了一个著名的日历错误：误将 1900 年视作闰年（平年本应只有 28 天，却加入了 `1900-02-29`）。
3. 随后微软开发 Excel 时为了 100% 兼容 Lotus 文件的数学模型，继承了这一设定。
4. 在现代数学计算中，基准日（Day 0）被固定在 **`1899-12-30 00:00:00 UTC`**。

### 3.2 整数：天数计算规则

以 **`1899-12-30`** 为基准零点进行天数线性偏移：

* **`0`** $\rightarrow$ `1899-12-30`
* **`1`** $\rightarrow$ `1899-12-31`
* **`2`** $\rightarrow$ `1900-01-01`
* **`5`** $\rightarrow$ `1899-12-30` 加 5 天 $\rightarrow$ **`1900-01-04`**（语雀与本系统标准）
* **`45565`** $\rightarrow$ `1899-12-30` 加 45565 天 $\rightarrow$ **`2024-09-30`**

### 3.3 负数：倒推日期规则（对齐语雀）

如果用户输入负数或公式相减出现负天数，语雀采用线性反向推算：

* **`-3`** $\rightarrow$ `1899-12-30` 减 3 天 $\rightarrow$ **`1899/12/27`**
* **`-5`** $\rightarrow$ `1899-12-30` 减 5 天 $\rightarrow$ **`1899-12-25`**

### 3.4 小数：时刻计算规则

一天共有 $24 \text{ 小时} = 1440 \text{ 分钟} = 86400 \text{ 秒}$。  
数值的小数部分直接代表当天的时刻百分比：

$$\text{当天的总秒数} = \text{小数部分} \times 86400$$

* **`.000`** $\rightarrow$ `00:00:00`（午夜零点，整数如 `5` 的时间默认全为 0）
* **`.250`** $\rightarrow$ $0.25 \times 24 = 6$ $\rightarrow$ `06:00:00`
* **`.500`** $\rightarrow$ $0.50 \times 24 = 12$ $\rightarrow$ `12:00:00`
* **`.750`** $\rightarrow$ $0.75 \times 24 = 18$ $\rightarrow$ `18:00:00`
* 示例：输入 **`5.5`** 配上“日期时间”格式，解析为 **`1900-01-04 12:00:00`**。

### 3.5 避免“历史时区污染”（UTC 绝对隔离）

在旧版实现中，若直接调用浏览器的 `new Date(ms).getHours()`，在东八区环境会将 1900 年解析出 `08:05:43` 的诡异时间。  
**原因**：中国在 1928 年前采用上海地方平时（LMT），时区偏移为 `GMT+08:05:43`。浏览器 V8 引擎严格遵守 IANA 历史时区表，自动补齐了该偏移。  
**解决方案**：核心格式化引擎在 `packages/core/src/format/number-format.ts` 中一律使用 **UTC 维度读取**（`getUTCFullYear`、`getUTCMonth`、`getUTCDate`、`getUTCHours` 等），杜绝历史时区与宿主环境时差的干扰。

## 4. 字符串输入解析规则

当单元格输入的内容为字符串时，引擎按优先级进行智能提取：

1. **标准年月日时间字符串**：
   - 匹配正则：`/^(\d{4})[-/.](\d{1,2})[-/.](\d{1,2})(?:\s+(\d{1,2}):(\d{1,2})(?::(\d{1,2}))?)?$/`
   - 支持分隔符：`-`、`/`、`.`（例如 `2024-05-01`、`2024/05/01`、`2024.05.01 13:45:00`）。
   - 提取各字段后构建无时区歧义的 `Date.UTC(Y, M, D, H, m, s)`。
2. **纯时间字符串**：
   - 匹配正则：`/^(\d{1,2}):(\d{1,2})(?::(\d{1,2}))?(?:\s*(AM|PM))?$/i`
   - 支持 12 小时制带 AM/PM（如 `1:00 PM` 转换为 13:00）与 24 小时制。
3. **无法转换的非法文本**（Fallback）：
   - 若输入为普通文本（如 `"hello"`、`"部门A"`）或不存在的无效日期（如 `"2024-02-31"`），引擎将安全回退：**原样保留文本展示**，不抛出异常。

## 5. 动态小数位调整规则（`.00 →` / `.00 ←`）

用户在工具栏点击“增加小数位数”或“减少小数位数”时：

1. 提取当前单元格格式中的小数位数：
   - 若已有格式串（如 `#,##0.00`），通过正则统计小数点后 `0` 的个数。
   - 若为常规格式（`General`），自动从当前数值的有效小数字符串推断初始小数位。
2. 根据点击动作执行 $\pm 1$（限制范围 `0 ~ 10` 位）。
3. 生成目标格式串（保持原有的千分位、货币符号或百分号特征）：
   - 普通数字：`#,##0` $\leftrightarrow$ `#,##0.0` $\leftrightarrow$ `#,##0.00`
   - 百分比：`0%` $\leftrightarrow$ `0.0%` $\leftrightarrow$ `0.00%`
   - 货币：`¥#,##0` $\leftrightarrow$ `¥#,##0.0` $\leftrightarrow$ `¥#,##0.00`
